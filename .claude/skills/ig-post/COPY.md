# 寫什麼

版型怎麼裝看 [`SKILL.md`](SKILL.md)。這份是內容。

輪播的成敗在兩個地方：**第一張有沒有人願意滑**，以及**滑完有沒有人想點連結**。
中間那幾張只要不讓人停下來就好。所以每一張都要削 ——
給到足夠讓人信，留到不夠讓人爽。

## 流程

1. 讀原文的**全文**。原文是網址就把整頁抓成純文字再讀 —— 不要拿 fetch／搜尋工具
   回傳的摘要當原文，摘要漏掉的句子你會誤判成「文章沒寫」，然後用自己的話補上去。
   抓出：核心主張、最反直覺的數字、最具體的痛（事故／帳單／時間點）、
   可逐字引用的句子。
2. 選骨架，**先只交分頁大綱**（每張一行：類型 + 一句話），等使用者確認再寫文案。
   大綱錯了才改很便宜，八張寫完才改很貴。
3. 寫文案 → caption → 配圖建議 → 灌進 studio 量。

## 骨架

封面 1 張 + 內頁 5～7 張。少於 5 張撐不出脈絡，多於 7 張沒人滑到底。
依原文的性質選一種，不要每篇都套同一個：

| 骨架       | 適合的原文         | 內頁順序                                                               |
| ---------- | ------------------ | ---------------------------------------------------------------------- |
| **論點型** | 主張 + 論證        | 定義／前提 → 具體的痛 → 論點主體（只講完整一個案例）→ 反面：什麼是例外 |
| **案例型** | 事故、專案復盤     | 起點 → 撞到什麼 → 試過但失敗 → 有效的做法 → 結果數字                   |
| **對照型** | 舊做法 vs 新做法   | 舊做法的代價 → 新做法是什麼 → 逐項對照 → 什麼情況下舊的還是對的        |
| **清單型** | N 個技巧、N 個工具 | 一張一項，最強的放最後一張內頁                                         |

**先寫「具體的痛」那張，再回頭寫封面** —— 封面是那個痛的一句話版本，
不是文章標題的複製。標題是給搜尋引擎的，hook 是給拇指的。

## 每一張標一個類型

類型決定文案結構，也決定配圖要什麼。標在輸出裡，讓使用者一眼看出節奏對不對。

`hook`（封面）、`body`（一個論點）、`stats`（單一數字）、`quote`（逐字引言）、
`comparison`（對照）、`process`（步驟／演進）、`list`（列點）、`cta`

同類型連續三張以上就是節奏死了，插一張 `stats` 或 `quote` 進去。

## 封面 hook

最重要的一張。這張失敗，後面寫得再好也沒人看到。挑一種：

| 類型        | 範例                                |
| ----------- | ----------------------------------- |
| 反直覺主張  | 你的 Harness 可能已經過期           |
| 提問        | 你的 CLAUDE.md 有幾條規則是多餘的？ |
| 數字 + 承諾 | 我砍掉三個 Harness，token 掉了一半  |
| 唱反調      | 別再寫 PLAN.md 了（改做這件事）     |
| 前後對比    | 以前寫 prompt，現在寫 loop          |

主標 14 字內、副標 18 字內。封面要有滑動暗示（`滑 →` 或箭頭），
沒有暗示的封面會被當成單圖直接滑過去。

## 留好奇缺口的四招

每篇至少用兩招，攤在不同張，不要全擠在最後。

- **點名不展開**：主體有三個案例，就完整講一個，另兩個講名字＋「那兩個爭議比較大」。
- **丟數字不解釋**：把原文最反直覺的數字單獨放一段，不說怎麼算的。
- **拋能力不教用法**：「其實已經內建了 X —— 但多數人沒用上」，句點。
- **明說裝不進**：「這條線沒辦法濃縮進一張圖」，承認格式限制，比硬塞可信。

**削掉的是推導，不是價值。** 最強的主張要放在最後一張內頁，讓人覺得滑到底有賺到；
缺口留在最後點名。順序倒過來（好料放前面、後面越來越空）會被當成標題黨。

底線：讀者滑完要能複述你的主張，只是缺推導。做不到就是削過頭了。

## 忠實度

引言、數字、時間點、人名、專有名詞一律回原文核對，逐字抄。原文說「Claude Code
5 小時的使用上限」就不能寫成「Claude 的使用上限」；別人論文量到的數字要帶出處
跟限定條件，不然等於把它講成自己的斷言。

**原文沒有的不補**：沒給的因果、沒說的結論、湊數的案例，全部不寫。
一張太稀的時候，能加的只有原文的實體內容 —— 加形容詞、加金句都是在製造落差，
讀者點進文章就會發現。削到剩一句話還是原文的意思，才算削對。

**用原文的句子，不要用自己的畫面。** 覺得某句「應該是這個意思」的時候，回去找那一句。
原文寫「已經是一段過期的 harness」，就不要改寫成「比我上週寫下來的摘要還新」——
後者讀起來更生動，但那是你想的，掛名的是作者。

**使用者給的舊草稿不算原文。** 前一版貼文、大綱、筆記都可能已經偏離文章，
沿用等於把偏差再蓋一次章。每一句都回文章核對，包含你自己上一輪寫的。

**每一張都要指得出來源小節。** 交付時附「頁 → 原文小節」對照表；指不出來的那張，
就是你自己寫的，砍掉或回去找。反過來也要查：對照表填完，看看原文有沒有整節
被你漏掉 —— 漏掉的往往是最有力的那段（有出處的引言、有版號的事實）。

## 讓它不像 AI 寫的

改完稿再過一遍，這幾個是實際犯過的：

| 症狀                                | 為什麼是問題               | 修法                                  |
| ----------------------------------- | -------------------------- | ------------------------------------- |
| 每張都「鉤子 → 展開 → 粗體金句」    | 格式一致性是最強的機器痕跡 | 粗體收束整篇最多 3 張，其餘平平地結束 |
| `不是 A，是 B`、`不只是 A`          | 高度過度代表的句型         | 只說你要說的那一件                    |
| 成對抽象（`一個…，一個…`）          | 同上                       | 留一個                                |
| bullet 講完了再用粗體句總結一次     | 分形總結                   | 刪粗體句                              |
| 「其實」「真正」「本質上」          | 填充詞                     | 刪掉，句意不變                        |
| 在別人的引言裡加粗                  | 替他決定重點               | 引用原封不動                          |
| 百科式補充（詞源、原意）            | 對一張 IG 沒有作用         | 刪                                    |
| 「總而言之」「這就是…的意義」當結尾 | 結論殘留                   | 內容講完就停                          |

不要反向過頭：乾淨的語法、正式的用詞、慣例的 CTA 都不是 AI 味。
要留 slack —— 有平凡的句子、有沒發展完的想法、有一張只用 60% 預算。

## 配圖建議

文案定稿後才配圖，而且**不是每張都要圖**。整篇挑 3～5 張，其餘留白。
判準只有一個：圖能不能省掉一段文字？省不掉就是裝飾。

| 該放                     | 為什麼                 |
| ------------------------ | ---------------------- |
| `hook`                   | 決定會不會有人滑第二張 |
| `comparison` / `process` | 一張圖打死一整段解釋   |
| `stats`                  | 單一大數字比一句話有力 |

每一張寫成一列：**位置｜類型（示意圖／對照圖／數據圖／截圖／情境照）｜
版位（banner 或 square）｜要傳達什麼（一句話）｜prompt**

prompt 指定主體、構圖、風格、配色、留白，並要求 **no text**
（中文字生出來會壞，字一律由版型疊上去）。範例：

> Minimal isometric diagram of two stacked layers, the lower one cracking apart,
> muted slate and warm amber accent, flat vector, generous negative space, no text, 16:9

**能截圖就不要生圖。** 終端機輸出、儀表板、程式碼、PR diff、帳單頁面，
真實截圖的說服力遠高於任何示意圖 —— 這類直接寫「截什麼、要框哪一段」。

視覺一致性比單張好看重要：整篇同一組配色、同一種字級節奏、同一個強調色。
看起來像八篇不同貼文，比八張都樸素更糟。

決定配圖之後那幾張的文字要重新量 —— 預算從 15 行掉到 10（banner）或 8（square）。

## 交付格式

逐張文案（標好 Slide N + 類型 + 該頁配圖與預算佔比）、「頁 → 原文小節」對照表、
caption、hashtag、配圖建議表，最後說明**哪幾張用了哪一招缺口**，
讓使用者判斷削得夠不夠。

caption 是縮小版的貼文，不是摘要：同一個痛開場 → 點名留了什麼沒講 → 導流
（連結放留言就寫「連結在留言」）。段落長度要不一，不要六段一樣長。
5～8 個 hashtag，混中英，跟內容對得上的才掛 —— 追流量的標會被看出來。

## 常見錯誤

| 錯誤                 | 後果                             | 修法                        |
| -------------------- | -------------------------------- | --------------------------- |
| 封面用文章標題       | 沒有拇指停下來                   | 換成〈封面 hook〉的五種之一 |
| 封面沒有滑動暗示     | 被當單圖滑過                     | 加 `滑 →`                   |
| 一張塞兩個論點       | 讀不完就跳走                     | 拆兩張                      |
| 好料放前面           | 滑到後面越來越空，被當標題黨     | 最強主張放最後一張內頁      |
| 缺口留成謎語         | 讀者不知道你在講什麼，不會點連結 | 主張要講完，只砍推導        |
| 每張都配圖           | 視覺吵，文字被壓縮               | 挑 3～5 張                  |
| 抽象概念配科技感藍線 | 圖沒有資訊量                     | 沒東西可畫就留白            |
| 補了原文沒說的結論   | 導流過去讀者發現落差             | 回原文核對                  |
| 拿摘要當原文         | 誤判「文章沒寫」，改用自己的話   | 抓全文純文字再讀            |
| 導流靠自動 CTA 頁    | 那是通用互動頁，不做導流         | 自己多開一張 `##`           |
