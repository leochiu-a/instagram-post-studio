# 寫什麼

版型怎麼裝看 [`SKILL.md`](SKILL.md)。這份是內容。

輪播的成敗在兩個地方：**第一張有沒有人願意滑**，以及**滑完有沒有人想點連結**。
中間那幾張只要不讓人停下來就好。所以每一張都要削 ——
給到足夠讓人信，留到不夠讓人爽。

## 流程

1. 讀原文的**全文**。原文是網址就把整頁抓成純文字再讀 —— 不要拿 fetch／搜尋工具
   回傳的摘要當原文，摘要漏掉的句子你會誤判成「文章沒寫」，然後用自己的話補上去。
   抓出：核心主張、最反直覺的數字、最具體的痛（事故／帳單／時間點）、
   可逐字引用的句子。
2. 選骨架，**先只交分頁大綱**（每張一行：類型 + 一句話），等使用者確認再寫文案。
   大綱錯了才改很便宜，八張寫完才改很貴。被當成 sub-agent 呼叫、沒有人可以回話時，
   這一步降級成「自己選一個骨架寫到底，把大綱附在最後的回報裡」，不要空等。
3. 寫文案 → 挑封面圖 → 寫成 `content/posts/<slug>.md` → 量（見 [`SKILL.md`](SKILL.md)）。

## 骨架

封面 1 張 + 內頁 5～7 張。少於 5 張撐不出脈絡，多於 7 張沒人滑到底。
依原文的性質選一種，不要每篇都套同一個：

| 骨架       | 適合的原文         | 內頁順序                                                                      |
| ---------- | ------------------ | ----------------------------------------------------------------------------- |
| **論點型** | 主張 + 論證        | 具體的痛 → 主張本身（帶出處）→ 論點主體（只講完整一個案例）→ 反面：什麼是例外 |
| **案例型** | 事故、專案復盤     | 起點 → 撞到什麼 → 試過但失敗 → 有效的做法 → 結果數字                          |
| **對照型** | 舊做法 vs 新做法   | 舊做法的代價 → 新做法是什麼 → 逐項對照 → 什麼情況下舊的還是對的               |
| **清單型** | N 個技巧、N 個工具 | 一張一項，最強的放最後一張內頁                                                |

**先寫「具體的痛」那張，再回頭寫封面** —— 封面是全篇最痛或最反直覺的那一件事的
一句話版本（結果型的數字也算，例如「上了九個 AI 功能，沒付一毛模型錢」），
不是文章標題的複製。標題是給搜尋引擎的，hook 是給拇指的。

**而且那張痛就放第一張內頁。** 原文為了寫成文章，前面通常會鋪定義、名詞解釋、
演進層次、四大分類這類東西 —— 那是文章的節奏，不是輪播的節奏。第一張內頁就
先講定義，讀者會直接滑走。這類「教科書段落」多半整節不要，真的需要就拆成
一句話塞進後面某張的第一段。

## 每一張標一個類型

類型決定文案結構，也決定配圖要什麼。寫大綱時標上去，讓使用者一眼看出節奏對不對；
定稿的 .md 裡不留這些標記。

`hook`（封面）、`body`（一個論點）、`stats`（單一數字）、`quote`（逐字引言）、
`comparison`（對照）、`process`（步驟／演進）、`list`（列點）、`cta`

同類型連續三張以上就是節奏死了，插一張 `stats` 或 `quote` 進去。

## 封面 hook

最重要的一張。這張失敗，後面寫得再好也沒人看到。挑一種：

| 類型        | 範例                                |
| ----------- | ----------------------------------- |
| 反直覺主張  | 你的 Harness 可能已經過期           |
| 提問        | 你的 CLAUDE.md 有幾條規則是多餘的？ |
| 數字 + 承諾 | 我砍掉三個 Harness，token 掉了一半  |
| 唱反調      | 別再寫 PLAN.md 了（改做這件事）     |
| 前後對比    | 以前寫 prompt，現在寫 loop          |

封面只有一個大標，版型沒有副標欄位。一行 10 字、2 行最穩、3 行是上限。

**不要自己加 `滑 →` 或箭頭。** 每一張非結尾頁都會自動渲染 SWIPE 膠囊
（`slide-card.tsx` 的 `SwipePill`），加了是重複，還白吃掉大標的一行。

hook 是那個痛的一句話版本。文章標題本身就是反直覺主張或提問的時候直接拿來用，
不用為了避開它硬掰一句 —— 要避開的是描述性的 SEO 標題，不是「標題」這件事。

## 留好奇缺口的四招

每篇至少用兩招，攤在不同張，不要全擠在最後。

- **點名不展開**：主體有三個案例，就完整講一個，另兩個講名字＋「那兩個爭議比較大」。
- **丟數字不解釋**：把原文最反直覺的數字單獨放一段，不說怎麼算的。
- **拋能力不教用法**：「其實已經內建了 X —— 但多數人沒用上」，句點。
- **明說裝不進**：「這條線沒辦法濃縮進一張圖」，承認格式限制，比硬塞可信。

**削掉的是推導，不是價值。** 最強的主張要放在最後一張內頁，讓人覺得滑到底有賺到；
缺口留在最後點名。順序倒過來（好料放前面、後面越來越空）會被當成標題黨。

底線：讀者滑完要能複述你的主張，只是缺推導。做不到就是削過頭了。

## 引言與列點的排版

版型只認得 `**粗體**`、`*斜體*`、`` `code` ``、`- ` 四種語法（細節看
[`SKILL.md`](SKILL.md)），原文的 `>` blockquote 搬過來會原封不動印出一個 `>`。

先分清楚那個 blockquote 是誰講的：**原文用 `>` 標自己的強調句時，它就是一般段落**，
拿掉 `>` 直接寫，不要加出處前綴 —— 加了會變成假引用。下面講的是真的引別人的話。

引言就自己站一段：前一行寫「誰（身分）：」，下一段是那句話本身，不加引號、
不加粗、不改寫。沒有具名個人的時候，前一行改寫出處
（「Anthropic 在一篇談 harness design 的文章裡寫：」）。

```md
Boris Cherny（Anthropic Claude Code 團隊負責人）：

I don't prompt Claude anymore. I have loops running that prompt Claude and figuring out what to do. My job is to write loops.
```

把引言縮成半句塞進自己的句子裡（「原文用的字是 they can quickly go stale」）
是最糟的處理 —— 既失去引言的重量，又讀起來卡。整句放不下就換一句短的引，
或者這張不引了。

列點也一樣要克制：原文的編號清單很好用，但一張 IG 上四個 bullet 就是一整片
灰色。**整篇 0 張列點是常態**，真的要用就一張、最多 4 點。

## 忠實度

引言、數字、時間點、人名、專有名詞一律回原文核對，逐字抄。原文說「Claude Code
5 小時的使用上限」就不能寫成「Claude 的使用上限」；別人論文量到的數字要帶出處
跟限定條件，不然等於把它講成自己的斷言。

**原文沒有的不補**：沒給的因果、沒說的結論、湊數的案例，全部不寫。
一張太稀的時候，能加的只有原文的實體內容 —— 加形容詞、加金句都是在製造落差，
讀者點進文章就會發現。削到剩一句話還是原文的意思，才算削對。而如果原文那一節
就只有這麼多，那張就讓它空著（`SKILL.md` 的用量規則允許一張只用 47%），
不要去隔壁小節搬材料 —— 那會變成一張塞兩個論點。

**原文自己就那樣寫的時候，忠實度優先。** 下一節列的那些句型（`不是 A，是 B`、
冒號帶出解釋）是在管你自己寫的句子。原文的原句就長那樣，就逐字留著 ——
為了躲一條去 AI 味的規則去改寫作者的句子，是把兩件事都做壞。

**用原文的句子，不要用自己的畫面。** 覺得某句「應該是這個意思」的時候，回去找那一句。
原文寫「已經是一段過期的 harness」，就不要改寫成「比我上週寫下來的摘要還新」——
後者讀起來更生動，但那是你想的，掛名的是作者。

**使用者給的舊草稿不算原文。** 前一版貼文、大綱、筆記都可能已經偏離文章，
沿用等於把偏差再蓋一次章。每一句都回文章核對，包含你自己上一輪寫的。

**每一張都要指得出來源小節。** 交付時附「頁 → 原文小節」對照表；指不出來的那張，
就是你自己寫的，砍掉或回去找。反過來也要查：對照表填完，看看原文有沒有整節
被你漏掉 —— 漏掉的往往是最有力的那段（有出處的引言、有版號的事實）。

## 讓它不像 AI 寫的

AI 味不在用詞，在**節奏**：每一張都同樣長、同樣結構、同樣用一句漂亮的話收尾。
讀者說不出哪裡怪，但滑八張的感覺像看八張同一個模板。

### 收尾

**最強的機器痕跡是「每張都用一句收束句結尾」。** 講完最後一件事就停，
不要回頭替這一張下定論。八張裡最多兩張是收束句 —— 通常是最痛的那張跟最後一張。

平平地結束長這樣：「這些在 2025 到 2026 年初大家都在討論，但隨著模型越來越強，
也慢慢淡出視野。」它沒有總結上面兩段，它只是講完了。

### 小標

小標不是每一張都要當 hook。整篇只有封面要搶人。內頁的小標可以是描述性的
（「經常撞到使用上限」）、直接就是那個專有名詞（「Loop Engineering」）、
或帶點口語的猶豫（「也許你不需要太多 harness」）。

八個小標都是精心設計的短句，本身就是機器痕跡。標題裡的 `不是 A，是 B` 也算。

### 具體的錨點

原文有時間、有團隊、有第一人稱的話，照抄那個具體性，不要抽象化：

- 「2026/03 前後，我們團隊常常有人說他又撞到 Claude Code 5 小時的使用上限」
- 「那陣子大家都在弄 harness」
- 「我在文章裡面把這件事講得更加完整」

改寫成「開發者經常面臨 token 消耗的挑戰」就死了。**時間、人、單位、版本號，
一律留著。**

### 句子

段落長度要參差。允許一張只有一句話（引言、金句），也允許一張有一段四行的敘述。
八張每張都是「兩到三段、每段兩到三句」就是模板。

沿用原文的寫法，包含它不一致的地方 —— 原文 harness 一下大寫一下小寫就跟著混用。
統一術語、統一句長、統一結構，都是把人味磨掉。

### 逐條檢查

改完稿再過一遍，這幾個是實際犯過的：

| 症狀                                | 為什麼是問題               | 修法                       |
| ----------------------------------- | -------------------------- | -------------------------- |
| 每張都「鉤子 → 展開 → 收束句」      | 格式一致性是最強的機器痕跡 | 只留兩張收束，其餘講完就停 |
| 每張小標都是設計過的 hook           | 同上                       | 內頁小標可以很平           |
| `不是 A，是 B`、`不只是 A`          | 高度過度代表的句型         | 只說你要說的那一件         |
| 冒號帶出解釋（「理由很現實：」）    | 講義腔                     | 直接講那件事               |
| 短斷言收句號、下一句才解釋          | 同一種講義腔，冒號換句號   | 併成一句（見下方〈句型〉） |
| 短句用逗號掛在長句尾巴              | 換了主詞，逗號接不住       | 斷開，主詞提到前面         |
| `當…，你會…`                        | 英文條件句直譯             | 刪「當」，第二人稱改陳述   |
| 名詞前疊三層以上修飾語              | 中文的堆疊上限比英文低     | 拆成兩句                   |
| 評價性的轉場（「數字也很誇張」）    | 你在替讀者反應             | 給數字就好                 |
| 成對抽象（`一個…，一個…`）          | 同上                       | 留一個                     |
| bullet 講完了再用粗體句總結一次     | 分形總結                   | 刪粗體句                   |
| 「其實」「真正」「本質上」          | 填充詞                     | 刪掉，句意不變             |
| 在別人的引言裡加粗                  | 替他決定重點               | 引用原封不動               |
| 百科式補充（詞源、原意）            | 對一張 IG 沒有作用         | 刪                         |
| 「總而言之」「這就是…的意義」當結尾 | 結論殘留                   | 內容講完就停               |

### 句型

上表前四條光看敘述不好認，各給一組對照：

**短斷言收句號、下一句才解釋** —— 最常犯的一種。

- 壞：`他們選地端的理由很現實。上架是每個賣家每天都在做的動作，雲端帳單會…`
- 好：`他們會選地端，是因為上架這個動作每個賣家每天都在做，雲端帳單會…`

先丟一句結論當標題、再補證據，是講義的結構不是講話的結構。

**短句用逗號黏在長句尾巴**

- 壞：`…你會開始做一些原本不划算的小功能，Yahoo 一口氣上了九個。`
- 好：`…但它跑一次不用錢。原本算下來不划算的小功能，Yahoo 一口氣上了九個。`

尾巴換了主詞也換了層次，一個逗號接不住。讓它自己當一句，主詞提前，數字才有地方掛。

**`當…，你會…`** 是英文 `when X, you start to Y` 的直譯。中文靠意合，「當」多半直接刪掉；「你會發現」「你會開始」也一起改成陳述句。

**修飾語堆疊**：`原本評估起來不划算的小功能` → `原本算下來不划算的小功能`，或拆成兩句。

寫完逐句掃一遍再定稿。這幾條在編輯器裡看不出來，要唸出聲。

不要反向過頭：乾淨的語法、正式的用詞、慣例的 CTA 都不是 AI 味。
要留 slack —— 有平凡的句子、有沒發展完的想法、有一張只用 60% 預算。

## 配圖建議

文案定稿後才配圖。**預設只有封面一張**，內頁留白 —— 內頁一放圖，預算就從 15 行
掉到 10（banner）或 8（square），等於拿三分之一的內容換一張圖。

圖片已經有了（原文的 hero、使用者指定的檔案、截圖）就只有兩個動作：複製到
`public/post-images/<slug>/`，正文寫 `![banner](/post-images/<slug>/<檔名>)`。
下面那些判準、prompt 寫法、配圖表都是「還要生圖」時才用得上的。

判準只有一個：圖能不能省掉一段文字？省不掉就是裝飾。會過這關的通常只有
`comparison` / `process`（一張圖打死一整段解釋）與 `stats`（單一大數字），
而且是原本就有的截圖，不是生出來的示意圖。整篇超過 3 張就是在裝飾。

每一張寫成一列：**位置｜類型（示意圖／對照圖／數據圖／截圖／情境照）｜
版位（banner 或 square）｜要傳達什麼（一句話）｜prompt**

prompt 指定主體、構圖、風格、配色、留白，並要求 **no text**
（中文字生出來會壞，字一律由版型疊上去）。範例：

> Minimal isometric diagram of two stacked layers, the lower one cracking apart,
> muted slate and warm amber accent, flat vector, generous negative space, no text, 16:9

圖片複製到 `public/post-images/<slug>/`，正文用相對路徑引用（貼外站網址匯出會撞
CORS）。

**能截圖就不要生圖。** 終端機輸出、儀表板、程式碼、PR diff、帳單頁面，
真實截圖的說服力遠高於任何示意圖 —— 這類直接寫「截什麼、要框哪一段」。

視覺一致性比單張好看重要：整篇同一組配色、同一種字級節奏、同一個強調色。
看起來像八篇不同貼文，比八張都樸素更糟。

決定配圖之後那幾張的文字要重新量 —— 預算從 15 行掉到 10（banner）或 8（square）。

## 交付格式

交付物是 `content/posts/<slug>.md` 這個檔案本身 —— 量過、`over` 全為 0 的那一份。
訊息裡附每頁的行數與佔比、「頁 → 原文小節」對照表，以及**哪幾張用了哪一招缺口**，
讓使用者判斷削得夠不夠。

類型標記、逐張大綱、配圖建議表是過程用的，不必再貼一次；caption 與 hashtag
等使用者要的時候再寫。

caption 是縮小版的貼文，不是摘要：同一個痛開場 → 點名留了什麼沒講 → 導流
（連結放留言就寫「連結在留言」）。段落長度要不一，不要六段一樣長。
5～8 個 hashtag，混中英，跟內容對得上的才掛 —— 追流量的標會被看出來。

## 常見錯誤

| 錯誤                          | 後果                             | 修法                           |
| ----------------------------- | -------------------------------- | ------------------------------ |
| 封面用描述性的 SEO 標題       | 沒有拇指停下來                   | 換成〈封面 hook〉的五種之一    |
| 封面自己加 `滑 →`             | 跟自動的 SWIPE 膠囊重複          | 刪掉，大標省下一行             |
| 一張塞兩個論點                | 讀不完就跳走                     | 拆兩張                         |
| 好料放前面                    | 滑到後面越來越空，被當標題黨     | 最強主張放最後一張內頁         |
| 缺口留成謎語                  | 讀者不知道你在講什麼，不會點連結 | 主張要講完，只砍推導           |
| 內頁也配圖                    | 預算掉到 10 行，內容被壓縮       | 預設只有封面一張               |
