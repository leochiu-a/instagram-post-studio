# 競品分析：Instagram 貼文／輪播製作工具

> 觀察日期：2026-08-20。介面會改版，引用時請對照當時的實際畫面重新確認。
> 觀察方式在每一節標明：「實際操作」是真的進到編輯器裡點過，
> 「公開素材」是只看得到官方截圖／示範影片／說明文件（該站有登入牆）。

這份文件的用途：ig-post-studio 之後要調版面或視覺時，先回來看這裡，
不要再從零推導一次。**結論在最後兩節**，前面是各家的實際觀察紀錄。

## 1. Canva

_觀察方式：公開素材（編輯器需登入，未註冊帳號）。結構取自其官方說明與產品截圖。_

編輯器固定分成四個區，**不管開哪種尺寸的設計，位置都不變**——官方明講這是為了建立肌肉記憶。

- **頂列**：滿版。左邊是檔名，中間 undo / redo，右邊 share 與 download。
- **左側面板**：所有「原料」的來源——範本、元素、上傳、文字、專案、App。以分頁切換。
- **中央畫布**：白色的版面本體，浮在中性底色上。
- **浮動工具列（Magic Bar）**：**只有選中物件時**才出現在畫布正上方，內容隨選取對象改變——
  選文字就變字型／字級／顏色，選照片就變去背／濾鏡。
- **頁面控制**：畫布正上方另有鎖定、複製、新增空白頁的圖示。

值得注意的是頁面管理跟物件編輯**是兩條不同的工具列**，都貼在畫布上方但職責分開。

**可借鏡**：四區固定不動的紀律；工具列「選中才出現」而不是常駐。
**不適用**：Canva 是通用拖拉畫布，本專案的內容來源是 markdown，不需要元素庫那一整套面板。

│ ➕ │   搜尋面板    │      └──────────────────────┘     │
│ T  │              │                                   │

│ 📁 │  設計資產     │        │              │          │
│ 🎨 │  影片／音樂   │        │    畫布      │          │
│ ▦  │              │        │              │          │

│ 🧩 │              │                        ⋯ 新增頁面 │
└────┴──────────────┴──────────────────────────────────┘

- **最左是 72px 的圖示 rail，每個圖示下面都有中文標籤**：
  搜尋／新增內容／文字／上傳／您的內容／品牌／範本／樣式／附加元件。
- rail 點開後，旁邊展開約 250px 的內容面板，面板右上角有 `×` 可以收掉，
  **收掉之後畫布就吃滿整個寬度**。
- 畫布浮在淺灰底上，沒有方格。
- **畫布上方浮著一條情境工具列**（編輯頁面／調整大小），不是常駐的資訊列。
- **新增頁面浮在右下角**，不佔用主要版面。
- 頂列右側依序是下載、分享、註冊——**只有這幾顆有顏色**。

**這一家最值得學的是配色紀律**：整個介面只有白、數階灰、以及一顆藍色的主要動作。
其餘零飽和度。畫面上唯一的顏色屬於使用者的作品。

## 3. PostNitro

_觀察方式：實際操作（官網的「演示輪播編輯器」，免登入）。_

- **左側 56px 圖示 rail**：人工智能／匯入／品牌／顏色／文本。同樣是圖示加標籤。
- **頂部一條浮動的分段工具列**：AI／模板／帆布／元素／…，做成膠囊狀漂在畫布上方，
  不是貼在視窗頂端的實體 bar。
- **slides 橫向並排**，左右各一顆 `‹` `›` 箭頭切換，目前這張置中放大、旁邊那張露出一角。
- 主要動作（創建輪播帖子）是綠色，其餘介面灰階。

**橫向排列是這一家給的最重要提示**：IG 輪播本來就是左右滑的，
把預覽排成橫向等於讓編輯時的空間關係跟成品的閱讀方式一致。

## 5. Contentdrips

_觀察方式：公開素材（官網首頁的產品示範影片逐格觀察；完整編輯器需註冊）。_

**輸入模型跟本專案最接近的一家。**

- 左側 rail：Import／Try AI／Templates／Canvas／Add Texts／Elements（圖示加標籤）。
- rail 旁的面板標題是 **AI Carousel Maker**，下面是來源分頁
  （Topic／Article／Youtube／Tiktok-Reel），再下面就是一個
  **「Write or paste your text post」的多行文字框**。
- 右側畫布底是**方格**，選中的 slide 上方浮出一條小工具列（刪除／複製／外框／下一張）。
- 頂列：undo／redo／指標工具／**SAVED 狀態**／連結／分享。

值得注意：它有一個明確的「已儲存」狀態指示，而本專案是存 localStorage、
使用者完全看不到存檔發生過。

## 抽出來的共同法則

1. **左側一定有圖示 rail。** 寬度 40–72px，點了才展開面板。
   有沒有這條 rail，決定了它看起來像「編輯器」還是像「一個表單旁邊放了張圖」。

2. **chrome 是灰階的，只有一顆主要動作有顏色。** 五家無一例外。
   畫面上唯一的顏色屬於使用者的作品——這是這類工具最重要的一條配色規則，
   因為介面存在的目的就是讓人判斷作品好不好看。
   語意色（destructive、ring、focus）也要一起壓，否則選取態會跟版型搶眼。

3. **工具列是浮動的、而且選中才出現。** 沒有一家在每一張預覽上常駐一條資訊列。

4. **頁面管理是獨立的一塊**，跟物件／內容的編輯分開：
   Express 放右下角浮著，輪播類的放成左右箭頭。

5. **方格底在專用輪播工具裡是常態**（aiCarousels、Contentdrips），
   通用工具（Express）則是純灰。方格不是裝飾，它讓縮放後的版型有參考線。

6. **輪播類專用工具把 slides 橫向排**，對上 IG 左右滑的閱讀方式；
   通用工具才是直向堆疊。

## 對 ig-post-studio 的意義

### 我們真正的差異點

Contentdrips 是唯一也走「貼一整段文字進去」的，但**它只在生成的那一刻用那段文字**，
之後就變成直接操作 slides，原文不再是真相來源。

ig-post-studio 的 markdown **是**真相來源，「套用到頁面」會整批重建。
這件事沒有任何一家在做，是這個工具唯一站得住的位置。
**任何版面調整都不該把 markdown 縮成一個小角落**——先前把它塞進 380px 側邊欄，
等於自願變成 Canva 的次等仿製品。

### 待辦（依 CP 值排序）

1. **把 chrome 洗成灰階**，訊號色只留給「匯出」一顆；選取態改用中性深色描邊，
   不用飽和色的 ring。只動 tokens，成本最低、效果最直接。
2. **加一條左側圖示 rail**（內容／設定／頁面），現在的側邊欄變成 rail 展開的面板，
   而且要能收合讓畫布吃滿。
3. **畫布方格加回來**（先前誤刪，理由是「Canva 是純灰底」——那是拿通用工具當參考，
   專用輪播工具其實都有方格）。
4. **讀數列改成 hover 才浮出、貼在該張上方的浮動列**，不要五張就五條常駐。
5. **預覽改成橫向 filmstrip**，對上 IG 的閱讀方式。
6. 補一個存檔狀態指示（現在存 localStorage，使用者完全看不到）。

### 明確不要抄的

- 元素庫／貼圖／音樂那一整套通用畫布的面板——本專案的版型是固定的。
- AI 生成內容的入口——本專案的輸入是使用者自己寫的 markdown。
- 浮水印、升級方案那些商業模式相關的介面元素。

## 6. Polotno Studio

_觀察方式：**實際操作，完整**（免登入、無限制）。這一輪最有價值的一個。_

一個開源的 Canva 式編輯器，很多社群貼文工具的底層就是它。
因為完全開放，可以把每一層面板都點開來看——這是前面九個都做不到的。

```
┌──────────────────────────────────────────────────────────┐
│ ▢ Polotno Studio │ 未命名设计            [下载 ▾]  ☰      │  ← 頂列
├────┬─────────────┬───────────────────────────────────────┤
│ ▦  │             │ ↶ ↷  ▪ Roboto ▾ ⋯   位置 ⊙ 🔒 ⧉ 🗑 ⇱ │  ← 情境屬性列
│模板 │             ├───────────────────────────────────────┤
│ ▩  │  文字面板    │                            ⧉  +       │  ← 頁面快捷
│素材 │             │        ┌─────────────────┐            │
│ 🎨 │  創建標題    │        │  ┌ ⧉ 🗑 位置 ┐  │            │  ← 浮動快捷列
│品牌 │  創建副標題  │        │  ╔═══════════╗  │            │
│ T  │  創建正文    │‹       │  ║   標題    ║  │            │  ← 藍色選取控制點
│文字 │             │↑       │  ╚═══════════╝  │            │

│Draw│             │        └─────────────────┘            │
│ ▤  │             │                                        │
│背景 │             │ [页面]        ⊖ 48% ⊕                 │  ← 收合的頁面抽屜
├────┴─────────────┴───────────────────────────────────────┤
│ ○ Edit as video   00:00/00:05  ⏮ ▶      [縮圖] +         │  ← 展開後的抽屜
└──────────────────────────────────────────────────────────┘
```

實際點過之後確認的四件事，**每一件都直接對應本專案的待辦**：

1. **chrome 是深色的。** 左 rail 近黑、面板深灰，畫布區才是淺灰。
   所以第一輪歸納的「chrome 要白」是錯的——正確的規則是 **chrome 要去飽和**，
   深或淺都成立（Figma、Photoshop、DaVinci 都走深色）。
   Polotno 整個介面**一點彩色都沒有**，連下載鍵都是白的。
   全畫面唯一的飽和色是**畫布上被選中物件的藍色控制點**——顏色只用在「你正在動的那個東西」上。

2. **頁面 filmstrip 是可收合的底部抽屜。** 預設收成左下角一顆「页面」小按鈕，
   點了才從底部滑出縮圖列。**這解決了我先前擔心的「filmstrip 會永久吃掉垂直空間」**——
   不必永久顯示。

3. **rail 旁的面板有收合把手**：面板右緣垂直置中一個 `‹`，收掉之後畫布吃滿整個寬度。
   Adobe Express 是面板右上角的 `×`，做法不同但意圖一樣。

4. **情境工具列有兩層**：
   - 頂端一整條**詳細屬性列**（顏色、字型、位置、鎖定、複製、刪除）
   - 貼在選中物件正上方的**浮動快捷列**（複製／刪除／位置）
     兩層都是選中才出現，沒選東西時頂端那條只剩 undo/redo。

## 7. Later

_觀察方式：官網產品畫面（app 需登入）。_

排程工具，但對本專案有用的是它的招牌功能 **Visual Planner**：

- 把已排程的貼文排成 **Instagram 的三欄 feed 格線**，放在一個手機外框裡，
  可以**拖曳互換位置**來預覽整個版面的視覺節奏。
- 格線上方有 格線／Reels 兩個檢視切換，還有「Show All Reels」開關。
- 每格右上角有小圖示標示貼文類型與排程狀態。

**對本專案的意義在清單頁**：一組 IG 貼文的正確隱喻是**作品集格線**，
不是檔案總管的列表。Later 甚至連手機外框都畫出來了，因為使用者要判斷的是
「這些東西擺在一起好不好看」。本專案的清單頁目前是純粹的檔案列表。

其餘（日曆、自動發布、分析）跟本專案無關，不細看。

## 8. Buffer

_觀察方式：官網產品畫面（app 需登入）。_

- 左側 **48px 純圖示 rail**，下半部是**已連結帳號的頭像堆疊**——
  rail 同時承擔「功能導覽」與「切換對象」兩件事。
- 主區是**內容日曆**（週檢視），頂端有 日曆／列表 檢視切換與多個篩選下拉。
- Create 頁則是**看板**（Unassigned / Review / Done 三欄），把貼文點子當卡片拖。

**值得記的是它的配色**：chrome 不是純白，是**暖調的米白**（約 `#F0EFEA`），
主要動作是**低飽和的柔綠**，不是鮮豔的品牌色。
證明第一輪歸納的「灰階」可以是**暖的**，也不必是純白——
重點在低飽和度，不在色相。這對本專案有直接參考價值，
因為之前選過的「暖紙檯面」方向其實跟 Buffer 是同一路。

## 9. Predis.ai

_觀察方式：公開素材，且**資訊很薄**（編輯器需註冊，官方文件也沒有介面說明）。_

定位是「一句 prompt → 完整輪播」：AI 寫文案、選版型、排好每一張。
編輯器本身據其官方說明是通用的拖拉系統——換版型、改字型顏色、
拉元素貼圖、上傳素材、把靜態輪播轉成動態影片。

**這一節沒有帶來新資訊。** 它的編輯器就是第一輪已經看過四次的那套骨架。
唯一值得記的是它的入口是**單一 prompt**，連貼一整段文字都不用——
跟本專案「使用者自己寫 markdown」是相反的哲學，不是可以借的東西。

## 10. Slideshows.Studio

_觀察方式：官網（產品本身需登入，但入口流程完全公開）。_

小而聚焦的產品，**野心規模跟本專案最接近**——不是要做通用設計工具。

首頁就是產品入口，沒有 dashboard：

- 一個**置中的單一輸入框**，上面掛 `From URL` / `From prompt` 分段切換。
- 下面一列**張數選擇**：`3` `5` `7` `10`，選中的那顆填實。
- 右側一顆紫色 CTA「Plan slideshow →」。
- 底下一行小字說明計費與「review and edit the AI plan before rendering」。
- 其餘整頁近乎灰階，大量留白。

**可借鏡的是這個「小工具不需要 dashboard」的判斷**：
整個產品的入口就是一個輸入框加幾顆選項，沒有側邊欄、沒有專案管理、沒有檢視切換。
本專案的清單頁其實也可以更接近這個形態。

另外它有一個「先給你看 AI 排的計畫、你確認過再算圖」的中間步驟，
對應到本專案就是「套用到頁面」前的預期管理——目前是一行警告文字，可以做得更好。

## 兩輪合併後，修正與新增的結論

### 修正第一輪的一條

> ~~「chrome 是灰階的」→ 我當時寫成白底＋一顆彩色主要動作。~~

正確的規則是 **chrome 要去飽和，明度可深可淺**：
Polotno 走深色、Buffer 走暖米白、Canva/Express 走白。
三種都成立，共同點是**低飽和**，不是特定色相或明度。
Polotno 更極端——chrome 零彩色，唯一的飽和色是畫布上被選中物件的控制點。

**推論**：顏色應該只用在「使用者正在動的那個東西」上，其餘一律讓給作品。
本專案的紫色 focus ring、紫色選取環、紫色匯出鍵**同時有三個地方在用彩色**，
其中只有「選中的那張預覽」符合這條規則。

### 新增三條

7. **頁面 filmstrip 可以收起來。** Polotno 預設收成一顆按鈕。
   本專案要加橫向 filmstrip 時不必擔心吃掉垂直空間——做成可收合的底部抽屜即可。

8. **rail 旁的面板要能收合到零寬**，讓畫布吃滿（Polotno 側邊把手、Express 面板 `×`）。
   本專案的側邊欄目前是寫死 380px、不能收。

9. **作品總覽的正確隱喻是 feed 格線，不是檔案列表**（Later 的 Visual Planner）。
   本專案的清單頁現在是「縮圖＋檔名＋中繼資料」的檔案總管形態。
